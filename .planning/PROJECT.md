# Phone Platform

Updated: 2026-11-11

## What This Is

Веб-сервис для руководителя и сотрудников, который собирает звонки из Телфина, показывает историю клиента, запись и расшифровку, оценивает диалог и помогает находить необработанные обращения. По образцу Bondscan используются его стек, разделение frontend/API/worker и Docker-запуск моделей через OpenCode.

## Core Value

Каждое доступное обращение видно в системе; руководитель понимает, что произошло, насколько качественно поговорил менеджер и кому ещё нужно перезвонить.

## Active Requirements

- Несколько независимых компаний с изоляцией данных и подключений с первого запуска.
- Получить всю доступную историю звонков по API Телфина, затем поддерживать её актуальной.
- Авторизация, подключение АТС, дашборд, журнал, подробная карточка с плеером и историей.
- Настраиваемые статусы и теги; ручное и автоматическое присвоение с историей изменений.
- Расшифровка и оценка диалога через отдельные ASR/LLM-провайдеры; Codex/OpenCode в Docker как исследуемые варианты.
- Определение первичного/повторного обращения с учётом границ доступной истории.
- Конструктор фильтров, включая «пропущен и не обработан через N часов».
- Интеграции со сделками amoCRM и Google Таблицами.
- Наблюдаемость, аудит, восстановление после сбоев и пилот на реальных данных.

## Validated

Реализована вся локальная платформа: Rust API/worker/shared crates, Vue интерфейс, авторизация и две изолированные компании, импорт/медиа/ASR/AI пайплайн, статусы/теги/фильтры/перезвоны, CRM/Sheets adapters, аудит/retention/backup. 47 различных Rust tests, 20 frontend unit, 13 Docker E2E без skips, 56 CLI offline tests, clean-volume Compose и реальное изолированное восстановление подтверждены. Подробнее `docs/pilot-report.md` и `STATE.md`.

Реальные аккаунты не подключались по предыдущему указанию пользователя; TEL-01…03/настоящее ASR-AI качество/CRM-Sheets live acceptance и пользовательский UAT остаются открыты. Demo не выдаётся за распознавание настоящей речи. Все фазы имеют код и локальные evidence; полнота внешних сервисов не объявлена проверенной.

Формулировка пользователя «текст и архитектуру» трактуется как «стек и архитектуру». Интерфейс и тексты нового продукта русские, предметные, без терминов брокерского сервиса. Маркетинговый копирайтинг не входит в технический старт.

## Confirmed User Decisions — 2026-11-11

- Сразу несколько независимых компаний с изолированными данными. Это обязательный scope v1, а не отложенная возможность расширения.
- «Легирование» означает **тегирование**: ручные и автоматические теги из исходного запроса. Логирование остаётся эксплуатационной функцией; создание лидов этим уточнением не запрашивалось.
- Доступ к API Телфина и записям уже есть. В проекте ещё требуется локально настроить credentials и проверить фактические права/принадлежность АТС; live-запросы пока не выполнялись.

## Working Assumptions — открытые параметры

- Onboarding компаний пока закрытый: оператор создаёт организацию и первого owner, далее owner приглашает сотрудников. Публичная SaaS-регистрация и биллинг не запрошены.
- Начальное окно истории — последние 30 дней как удобный preset; произвольный период и режим «вся доступная история» обязательны. Пользователь ещё не задал глубину и нагрузку.
- Пропущенное обращение закрывает успешный исходящий разговор с тем же клиентом; успешный повторный входящий также закрывает обращение по настройке. Попытка без ответа учитывается отдельно.
- Порог ожидания по умолчанию 2 часа календарного времени; рабочие часы и часовой пояс настраиваются. Это предложение, а не подтверждённое правило бизнеса.
- Обе интеграции входят в v1; порядок amoCRM/Sheets можно поменять после ответа пользователя.
- Для каждой компании — собственные подключения Телфина, секреты, теги, статусы, шкалы оценки, фильтры, интеграции и данные. Тариф/квоты ASR и LLM ещё не выбраны; секреты настраиваются владельцем в готовом интерфейсе, ключи runner — оператором локально.

## Constraints

- Не смешивать данные и инфраструктуру Bondscan с новым сервисом.
- Не считать «первая запись в нашей БД» доказательством первого обращения клиента.
- Не оценивать разговор без достаточного текста и определения участников.
- Импорт метаданных не зависит от наличия записи или работоспособности ASR/LLM.
- Фактические ограничения Телфина проверяются контрактным spike перед production-коннектором.

## Key Decisions

| Решение | Причина | Статус |
|---------|---------|--------|
| Rust API + Rust worker + Vue SPA, PostgreSQL + RabbitMQ | Прямое соответствие Bondscan | Принято как основа |
| Один monorepo с общими контрактами | Атомарные изменения нового небольшого продукта | Реализовано |
| Несколько компаний с изоляцией с первого запуска | Прямое уточнение пользователя | Подтверждено пользователем |
| Тегирование | Уточнено значение «легирования» | Подтверждено пользователем |
| Доступ Телфин API и записи уже есть | Подключаем имеющиеся доступы локально | Подтверждено пользователем; live не проверен |
| API spike первым | Рано проверить доступ и полноту истории | Принято из запроса |
| ASR отдельно от LLM, провайдеры заменяемы | Аудио и оценка — разные задачи | Принято архитектурно |
| OpenCode V1 из образца не обновлять вслепую до V2 | Новый CLI/SDK требует проверки совместимости | Проверка в фазе 6 |
| Ручной override и unknown обязательны | Надёжность автоматической разметки | Принято архитектурно |

## Out of Scope for v1

Собственная IP-АТС, совершение/перехват звонков, речевой бот в реальном времени, мобильные приложения, публичный биллинг, автоматическая смена этапа сделки без явно включённого правила. Создание лидов не относится к уточнённому требованию о тегировании.

## Evolution

После каждой фазы обновлять решения, проверенные требования, ограничения и STATE. Изменения пользовательских ответов распространять на требования, планы и проверки.
