# Requirements: Phone Platform

Defined/updated: 2026-11-11. Реализация всех разделов существует; ниже разделены техническая локальная проверка и внешняя приёмка. [x] означает доказанный локальный критерий на синтетике/настоящем локальном HTTP/БД/Docker, а не пользовательский UAT или гарантию качества внешнего провайдера. Для live-зависимых требований checkbox остаётся открытым; SYNC-02 имеет явное отклонение (polling вместо webhook).

Фактические evidence: [pilot-report](../docs/pilot-report.md), [independent verifier](reviews/FINAL-VERIFICATION.md), [execution delta](research/EXECUTION-DELTA.md). Финальный пользовательский UAT ожидается по [сценариям](../docs/uat.md).

## v1 Requirements

### API Телфина и импорт

- [ ] **TEL-01**: Локальный CLI получает доступ к API и безопасно сообщает доступную АТС и права, не раскрывая секреты.
- [ ] **TEL-02**: CLI выгружает все страницы за произвольный период, включая режим всей доступной истории, входящие, исходящие, внутренние, пропущенные и без записи.
- [ ] **TEL-03**: Отчёт выгрузки показывает границы периода, количество логических звонков/плеч, ошибки, ограничения полноты и результат сверки контрольного периода с Телфином.
- [ ] **SYNC-01**: Production-коннектор выполняет идемпотентный исторический импорт с checkpoint, повторным запуском и отображением прогресса.
- [ ] **SYNC-02**: Новые и поздно изменённые звонки поступают через периодическую сверку с перекрытием; события АТС ускоряют обновление без замены сверки.
- [ ] **SYNC-03**: Различаются звонок и плечи; перевод или ответ другим сотрудником не создаёт ложный пропущенный клиентский звонок.
- [ ] **SYNC-04**: Сбой, истечение токена, 429 и повторная доставка не теряют данные; есть ограниченные retry, DLQ и видимая причина ошибки.

### Платформа и доступ

- [x] **PLAT-01**: Независимый Docker Compose запускает API, worker, client, PostgreSQL, RabbitMQ и приватное хранилище; миграции воспроизводимы.
- [x] **AUTH-01**: Пользователь входит, восстанавливает доступ и выходит; сессия сохраняется после перезагрузки и отзывается сервером.
- [x] **AUTH-02**: Несколько независимых компаний работают с первого запуска. Роли owner, manager, reviewer действуют внутри компании; сервер проверяет членство при выборе компании. Данные, подключения и секреты, теги/статусы, критерии оценки, фильтры, интеграции, фоновые задачи, выгрузки и медиа изолированы; переключение компании не оставляет чужие данные в интерфейсе.
- [x] **AUTH-03**: Владелец приглашает сотрудника, сопоставляет его с добавочным Телфина и управляет доступом без публичной регистрации.
- [ ] **CONN-01**: Владелец подключает/отключает Телфин, проверяет соединение, задаёт период импорта и видит его состояние; секреты доступны только серверу.

### Журнал и карточка

- [x] **CALL-01**: Пользователь видит пагинируемый журнал, даты, направление, клиента, сотрудника, длительность, результат звонка, разметку и состояние анализа.
- [x] **CALL-02**: Карточка показывает плечи/переводы, технические данные, историю клиента, ручные пометки и понятные loading/empty/error состояния.
- [x] **CALL-03**: Доступная запись воспроизводится с перемоткой; отсутствие/истечение/ожидание записи отображается явно, доступ проверяется сервером.
- [x] **TAG-01**: Владелец создаёт, переименовывает и архивирует бизнес-статусы и теги; технические результаты АТС сохраняют собственный смысл.
- [x] **TAG-02**: Пользователь исправляет разметку с указанием автора; повторный анализ не перетирает ручные решения.

### Расшифровка и анализ

- [ ] **ASR-01**: Worker получает запись и строит версионированную расшифровку с временными сегментами и обозначением говорящих; неопределённость ролей видна.
- [ ] **ASR-02**: Длинное, шумное, повреждённое или отсутствующее аудио имеет управляемый исход; повторная обработка идемпотентна, провайдер настраивается.
- [ ] **AI-01**: Изолированный Docker runner анализирует текст через проверенный OpenCode/Codex либо другой совместимый адаптер; модель выбирается настройкой.
- [x] **AI-02**: Результат содержит резюме, намерение клиента, договорённости, следующие шаги и предложения тегов/статуса с цитатами и временем; строгая схема валидируется.
- [x] **AI-03**: Владелец настраивает версионированную шкалу оценки; карточка показывает критерии, применимость, доказательства и общий балл либо «недостаточно данных».
- [x] **AI-04**: Тип обращения принимает значения первичное, повторное, неизвестно; опирается на историю до звонка, покрытие импорта и смысловую разметку с объяснением.
- [x] **AI-05**: Сохраняются модель, версии промпта/критериев/расшифровки, история запусков, лимиты затрат и ошибок; плохой ответ не превращается в подтверждённую разметку.

### Фильтры и контроль обработки

- [x] **FLT-01**: Фильтры по периоду, направлению, сотруднику, результату, типу обращения, тегам, статусу, баллу и состоянию анализа работают совместно.
- [x] **FLT-02**: Конструктор AND/OR/NOT с типизированными операторами сохраняет представления; сервер проверяет поля, сложность и доступ.
- [x] **FLT-03**: Представление «пропущен и не обработан через N часов» учитывает успешные контакты, отдельно показывает попытки, настройки рабочего времени и полноту истории; его счётчик на дашборде ведёт в ту же выборку.
- [x] **FLT-04**: Просрочка обновляется по времени даже без новых звонков; поздний импорт и исправление данных пересчитывают связанные обращения.

### Интеграции

- [ ] **CRM-01**: Владелец подключает amoCRM; пользователь видит связанные контакт/сделку, неоднозначное совпадение выбирает вручную.
- [ ] **CRM-02**: Результат звонка и ссылка отправляются в выбранную сделку как событие/примечание идемпотентно; изменение этапов и создание лидов требуют отдельного правила.
- [ ] **SHEET-01**: Владелец подключает Google Таблицу и задаёт соответствие колонок; выбранные звонки и результаты обновляются по стабильному ключу без дублей.
- [ ] **INT-01**: Обе интеграции имеют независимые retries, журнал синхронизации, видимый отказ доступа и безопасное отключение.

### Дашборд и эксплуатация

- [x] **DASH-01**: Базовый дашборд показывает количество, направления и технические результаты звонков, включая пропущенные, с переходом к соответствующему списку. Метрика необработанных/просроченных обращений добавляется в фазе 7 по FLT-03.
- [x] **DASH-02**: Руководитель видит динамику, распределение оценок и показатели сотрудников; знаменатели и исключения понятны, агрегаты сверяются с журналом.
- [x] **OPS-01**: Журнал аудита фиксирует изменения правил, разметки, подключений и доступа; технические логи не раскрывают токены и содержание разговоров.
- [x] **OPS-02**: Видны задержка импорта, очереди, ошибки ASR/AI/интеграций, расход провайдеров; есть ручной retry и управляемый reprocess.
- [x] **OPS-03**: Настроены сроки хранения, удаление связанных аудио/текста/производных данных, резервные копии и проверенное восстановление.
- [ ] **REL-01**: Пилот проходит сценарии полного пути и негативные случаи, сверку импорта с АТС, нагрузочную проверку и согласование качества разметки.

## Phase 11 — configuration assistant (2026-11-12)

Семь новых требований дополнительно к 38 baseline. Внешняя приёмка модели/авторизации/Телфина не подменяется fixtures.

- [ ] **CHAT-01**: Чат-панель/FAB и полная страница, история/rename/delete и русские подсказки в границах своей компании/пользователя; отмена поздних ответов при смене компании.
- [ ] **CHAT-02**: Сохранённые partial/run/tool states, terminal success/error/cancel, idempotent requests/recovery и объяснимый audit действий; потеря транспорта не означает rollback.
- [ ] **CHAT-03**: Защищённая карточка принимает доступы Телфина внутри чата; encrypted refs/expiry, нет plaintext в prompt/history/events/audit/logs, проверки user/org/conversation.
- [ ] **CODEX-01**: Отдельный pinned Docker Codex runtime без БД/репозитория/socket/host auth; ограниченный ephemeral turn, подавление встроенных инструментов/host RPC и cleanup. Анализатор MCP0 не ослаблен.
- [ ] **CODEX-02**: Собственная приватная для компании авторизация Codex device code/API key через UI; status/error/logout/cancel. Без авторизации ответ модели не имитируется.
- [ ] **MCP-01**: Настоящий SDK stdio MCP bridge с восемью типизированными инструментами; проверки исходной сессии/org/owner/run/TTL на каждый вызов, атомарные idempotent mutation/audit/CAS. Нет произвольных HTTP/SQL/IAM/retention/export.
- [ ] **SETUP-01**: По сообщению в чате помощник подключает/проверяет Телфин и запускает импорт; создаёт/обновляет статусы, теги, фильтры, шкалу и правила перезвона. UI показывает фактически применённые результаты. Реальные модельное качество и доступ Телфина проверяются после настройки аккаунтов.
