# Requirements: Phone Platform

Defined: 2026-11-11. Все пункты Pending до проверки реализации.

## v1 Requirements

### API Телфина и импорт

- [ ] **TEL-01**: Локальный CLI получает доступ к API и безопасно сообщает доступную АТС и права, не раскрывая секреты.
- [ ] **TEL-02**: CLI выгружает все страницы за произвольный период, включая режим всей доступной истории, входящие, исходящие, внутренние, пропущенные и без записи.
- [ ] **TEL-03**: Отчёт выгрузки показывает границы периода, количество логических звонков/плеч, ошибки, ограничения полноты и результат сверки контрольного периода с Телфином.
- [ ] **SYNC-01**: Production-коннектор выполняет идемпотентный исторический импорт с checkpoint, повторным запуском и отображением прогресса.
- [ ] **SYNC-02**: Новые и поздно изменённые звонки поступают через периодическую сверку с перекрытием; события АТС ускоряют обновление без замены сверки.
- [ ] **SYNC-03**: Различаются звонок и плечи; перевод или ответ другим сотрудником не создаёт ложный пропущенный клиентский звонок.
- [ ] **SYNC-04**: Сбой, истечение токена, 429 и повторная доставка не теряют данные; есть ограниченные retry, DLQ и видимая причина ошибки.

### Платформа и доступ

- [ ] **PLAT-01**: Независимый Docker Compose запускает API, worker, client, PostgreSQL, RabbitMQ и приватное хранилище; миграции воспроизводимы.
- [ ] **AUTH-01**: Пользователь входит, восстанавливает доступ и выходит; сессия сохраняется после перезагрузки и отзывается сервером.
- [ ] **AUTH-02**: Роли owner, manager, reviewer ограничивают просмотр и изменения; данные, фоновые задачи, выгрузки и медиа изолированы по компании.
- [ ] **AUTH-03**: Владелец приглашает сотрудника, сопоставляет его с добавочным Телфина и управляет доступом без публичной регистрации.
- [ ] **CONN-01**: Владелец подключает/отключает Телфин, проверяет соединение, задаёт период импорта и видит его состояние; секреты доступны только серверу.

### Журнал и карточка

- [ ] **CALL-01**: Пользователь видит пагинируемый журнал, даты, направление, клиента, сотрудника, длительность, результат звонка, разметку и состояние анализа.
- [ ] **CALL-02**: Карточка показывает плечи/переводы, технические данные, историю клиента, ручные пометки и понятные loading/empty/error состояния.
- [ ] **CALL-03**: Доступная запись воспроизводится с перемоткой; отсутствие/истечение/ожидание записи отображается явно, доступ проверяется сервером.
- [ ] **TAG-01**: Владелец создаёт, переименовывает и архивирует бизнес-статусы и теги; технические результаты АТС сохраняют собственный смысл.
- [ ] **TAG-02**: Пользователь исправляет разметку с указанием автора; повторный анализ не перетирает ручные решения.

### Расшифровка и анализ

- [ ] **ASR-01**: Worker получает запись и строит версионированную расшифровку с временными сегментами и обозначением говорящих; неопределённость ролей видна.
- [ ] **ASR-02**: Длинное, шумное, повреждённое или отсутствующее аудио имеет управляемый исход; повторная обработка идемпотентна, провайдер настраивается.
- [ ] **AI-01**: Изолированный Docker runner анализирует текст через проверенный OpenCode/Codex либо другой совместимый адаптер; модель выбирается настройкой.
- [ ] **AI-02**: Результат содержит резюме, намерение клиента, договорённости, следующие шаги и предложения тегов/статуса с цитатами и временем; строгая схема валидируется.
- [ ] **AI-03**: Владелец настраивает версионированную шкалу оценки; карточка показывает критерии, применимость, доказательства и общий балл либо «недостаточно данных».
- [ ] **AI-04**: Тип обращения принимает значения первичное, повторное, неизвестно; опирается на историю до звонка, покрытие импорта и смысловую разметку с объяснением.
- [ ] **AI-05**: Сохраняются модель, версии промпта/критериев/расшифровки, история запусков, лимиты затрат и ошибок; плохой ответ не превращается в подтверждённую разметку.

### Фильтры и контроль обработки

- [ ] **FLT-01**: Фильтры по периоду, направлению, сотруднику, результату, типу обращения, тегам, статусу, баллу и состоянию анализа работают совместно.
- [ ] **FLT-02**: Конструктор AND/OR/NOT с типизированными операторами сохраняет представления; сервер проверяет поля, сложность и доступ.
- [ ] **FLT-03**: Представление «пропущен и не обработан через N часов» учитывает успешные контакты, отдельно показывает попытки, настройки рабочего времени и полноту истории; его счётчик на дашборде ведёт в ту же выборку.
- [ ] **FLT-04**: Просрочка обновляется по времени даже без новых звонков; поздний импорт и исправление данных пересчитывают связанные обращения.

### Интеграции

- [ ] **CRM-01**: Владелец подключает amoCRM; пользователь видит связанные контакт/сделку, неоднозначное совпадение выбирает вручную.
- [ ] **CRM-02**: Результат звонка и ссылка отправляются в выбранную сделку как событие/примечание идемпотентно; изменение этапов и создание лидов требуют отдельного правила.
- [ ] **SHEET-01**: Владелец подключает Google Таблицу и задаёт соответствие колонок; выбранные звонки и результаты обновляются по стабильному ключу без дублей.
- [ ] **INT-01**: Обе интеграции имеют независимые retries, журнал синхронизации, видимый отказ доступа и безопасное отключение.

### Дашборд и эксплуатация

- [ ] **DASH-01**: Базовый дашборд показывает количество, направления и технические результаты звонков, включая пропущенные, с переходом к соответствующему списку. Метрика необработанных/просроченных обращений добавляется в фазе 7 по FLT-03.
- [ ] **DASH-02**: Руководитель видит динамику, распределение оценок и показатели сотрудников; знаменатели и исключения понятны, агрегаты сверяются с журналом.
- [ ] **OPS-01**: Журнал аудита фиксирует изменения правил, разметки, подключений и доступа; технические логи не раскрывают токены и содержание разговоров.
- [ ] **OPS-02**: Видны задержка импорта, очереди, ошибки ASR/AI/интеграций, расход провайдеров; есть ручной retry и управляемый reprocess.
- [ ] **OPS-03**: Настроены сроки хранения, удаление связанных аудио/текста/производных данных, резервные копии и проверенное восстановление.
- [ ] **REL-01**: Пилот проходит сценарии полного пути и негативные случаи, сверку импорта с АТС, нагрузочную проверку и согласование качества разметки.

## v2 / уточнение

Публичная SaaS-регистрация и биллинг, real-time подсказки менеджеру, исходящие звонки из интерфейса, другие АТС. Лидирование уточнить после ответа на вопрос о «легировании».
