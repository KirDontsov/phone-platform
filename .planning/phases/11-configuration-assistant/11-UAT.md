# Фаза 11 — приёмка помощника настройки

Автоматическая локальная приёмка выполнена на настоящем API/PostgreSQL/MCP и отдельном тестовом runtime. Настоящие аккаунты, model inference и Телфин по предыдущему указанию пользователя не вызывались. Пользовательские пункты ниже остаются **Pending**; фиктивный wire ответ не засчитывается вместо них.

## Автоматически проверено

| Сценарий | Результат / среда |
| --- | --- |
| Чужая компания/пользователь/reviewer не читают private chat/credential/run и не выполняют tools | PASS — Actix/PG и browser scope |
| Logout, switch, loss of owner, cancel во время ожидания lock запрещают позднее изменение | PASS — настоящие много-соединительные PG barriers |
| Уже committed tool сохраняется после Stop; незавершённое действие не называется успешным | PASS — receipt/event API assertions; browser hold/cancel |
| Повторы сообщений/tools, stale CAS/version, ошибки nested schema и лимит24 | PASS — durable receipts/budget, результат из реальной БД |
| Raw секрет не попадает в history/events/audit/model context; ciphertext уничтожается при consume/expiry | PASS — synthetic sentinel и physical maintenance |
| Восстановление не возвращает удалённые chats/credential refs и отзывает прежний auth/capability | PASS — два actualPG restore tests и isolated snapshot restore |
| Реальный Codex executor не выполняет forced exec_command; реальный SDK вызывает только fixed gateway | PASS — pinned native/Docker, offline Responses fixture,0paid calls |
| Без auth нет модельного ответа, история/reload/mobile/защищённая форма работают | PASS — actual Docker noauth и isolated configured fixture browser |

Точные команды, provenance, количества и границы: [11-VERIFICATION](11-VERIFICATION.md). Автоматические повторы не считаются новыми различными сценариями.

## Финальный пользовательский тест

Открыть `http://localhost:18081`, войти владельцем нужной компании и открыть «Помощник». Можно пользоваться полной страницей или кнопкой чата. Реальные ключи вводить только в защищённые формы, не в обычное сообщение.

1. **Войти в Codex — Pending.** Выбрать вход по коду устройства либо API key. Ожидается настоящий status «Подключено». Отмена/выход возвращают состояние «Требуется подключение». Ошибки policy/entitlement должны показываться явно; отсутствие модели не заменяется демонстрационным ответом.
2. **Передать Телфин — Pending.** В «Добавить доступы» заполнить App ID, App Secret и числовой Client ID или вставить JSON в этой форме. Ожидается карточка защищённых доступов, без секретов в сообщениях/истории. Отправить новую задачу с этим ref; не требуется редактировать env вручную.
3. **Запустить настройку — Pending.** Например: «Подключи Телфин, проверь соединение и загрузи всю доступную историю. Создай статусы “Первичное обращение” и “Повторное обращение”, тег “Нужно перезвонить” и фильтр для пропущенных без разговора с сотрудником более двух часов». Ожидаются реальные tool outcomes и настройки в обычных разделах. Ошибка провайдера или queued import не должны называться завершённой загрузкой.
4. **Проверить полезность и точность — Pending.** Сверить настройки и результаты загрузки с Телфином. Первичность — вычисление по известной истории, answered IVR не считается разговором с сотрудником; неполнота истории остаётся видимой. Если нужны иные правила, уточнить их обычным сообщением и проверить фактическое изменение.
5. **Проверить историю и Stop — Pending.** Перезагрузить страницу во время/после задачи: сообщения и реальные результаты сохраняются. Нажать «Остановить» на длительной задаче: новые действия прекращаются; уже выполненные остаются. При потерянной связи UI сверяет сохранённый run и не обещает rollback.
6. **Проверить компании — Pending.** Переключиться в другую компанию: предыдущий чат/ref не отображаются и не действуют. Вернуться в исходную компанию — собственная сохранённая история доступна. Секретные формы после переключения пустые.

Для найденного дефекта достаточно указать компанию, время, текст задачи, ожидаемый результат и видимый безопасный error code/run ID. Не прикладывать ключи/токены или реальные номера клиентов в обычный issue/чат. Приёмка по paid model usage, Телфину и итоговому UX закрывается только после этих фактических действий владельца.
