# План: рабочий экран и прозрачная обработка

## Контракт результата

1. Журнал/Dashboard имеют видимые теги, бизнес-статус, тип контакта, состояние анализа и согласованные фильтры. Правая панель позволяет разметить звонок без ухода со списка. Используется ширина экрана, mobile390 без overflow.
2. Фильтр «без успешного перезвона не менее X часов» с произвольным X (в пределах безопасного диапазона); дополнительное «не было попыток» отдельно. Сохраняется относительный AST, история до фильтров, uncertain отдельно. Dashboard aggregate/list используют один фильтр.
3. Call/detail processing projection различает готовую расшифровку/готовый анализ, активные jobs, retry/error, provider unavailable; нет ложного «в очереди» для demo-only ASR реального звонка. Дубликат active job не создаётся; preflight проверяет prerequisites/конфигурацию, stale/succeeded wrapper не скрывает дочерний job. Количество задач относится только к собственной компании, ETA неизвестен. Автообновление detail/status.
4. Произвольные rubric criteria: текст инструкции, weight/required/version + evaluation_mode score/checklist. Checklist даёт fulfilled true/false/null с доказательствами; отсутствие доказательств не превращается в «нет», неизвестные роли ограничивают вывод. Старые rubric/analysis совместимы. Manual overrides/история сохраняются.
5. amoCRM связь и отправка остаются явными. Sheets выбранная произвольная таблица/лист на компанию: понятное поле→колонка, стабильный call key, summary/agreements/next_steps/criteria поддерживаются. Документирован сценарий «выгрузка в служебный лист → выбор ячеек/IMPORTRANGE в другие таблицы». Множество одновременных destinations и произвольная запись поверх пользовательских ячеек не входят; ограничение явно показано в UI.

Call получает `transcript_state: ready|missing`, `analysis_state: analyzed|partial|not_analyzed`, `processing:{state:idle|queued|running|retry|failed|completed|skipped,step:transcribe|analyze|reprocess|null,job_id,error_code,queued_at,updated_at,next_attempt_at,attempts,max_attempts}`. Detail получает `processing:{...Call.processing,queue:{scope:organization,ready_ahead:number|null,ready_total,running_total,scheduled_total,estimated_wait_seconds:null},providers:{asr:{ready:boolean,reason:string|null},analysis:{ready:boolean,reason:string|null}}}`. Только анализ актуальной версии transcript даёт analyzed/partial; partial — настоящий результат с abstention/null score, прежние результаты остаются в history. `callback_age_minutes`/`callback_attempts` — numeric|null на первом звонке эпизода. Queue не раскрывает чужие компании/payload/lease data. Preflight под блокировкой звонка сначала возвращает уже активный wrapper/child (202), затем проверяет доступность: transcribe требует ready recording+ASR, analyze — ready transcript+analysis+active rubric, all — recording+ASR+analysis+rubric; all сохраняет прежнюю семантику новой расшифровки. Ни один preflight не вызывает внешнюю модель.
