# ASR и анализ через Codex/OpenCode

Research date: 2026-11-11. Документация проверена; запуск на реальных звонках ещё не выполнен.

## Возможность и границы

Официальный Codex SDK позволяет программно запускать локальные Codex threads на сервере. Это делает адаптер технически возможным; пригодность для оценки русских телефонных диалогов, доступ к выбранной модели, квоты, стоимость и воспроизводимость должны быть измерены в фазе 6. Наличие Codex в текущем чате не доказывает доступность фонового production backend.

ASR — отдельный контракт `TranscriptionProvider`, оценка текста — `AnalysisProvider`. Расшифровка должна уметь возвращать временные сегменты и сведения о говорящих либо явно сообщать об их отсутствии. Не считать все coding models аудиомоделями.

Документация OpenAI file transcription описывает лимит файла и поддерживаемые форматы. Такие ограничения проверяются у выбранного ASR при реализации; нужны chunking и сборка временных смещений. Выбор модели задаётся конфигурацией, имена не зашиваются в доменную модель. Специализированные старые примеры diarization могут быть deprecated — не выбирать их без проверки актуального lifecycle.

## OpenCode из образца

В Bondscan используется семейство V1: пакет plugin 1.18.10 и CLI-вызов. Официальный сайт теперь ведёт на V2, а страница `v1/docs/server` прямо помечена как прежняя версия. Поэтому spike должен выбрать: закрепить работоспособный V1 из образца либо проверить V2 и оформить отдельный adapter. Не смешивать конфиг разрешений и протоколы разных major versions.

Предпочтительный первый путь по запросу пользователя: проверенный pinned OpenCode CLI в Docker, provider/model из runtime config. Вариант Codex SDK/CLI — самостоятельный adapter, сравниваемый на том же наборе, без обещания совместимости произвольной Codex OAuth-учётки с OpenCode. OpenAI-compatible HTTP и локальная модель — возможные альтернативы, также требуют smoke test.

## Контракт результата

`schema_version`, `summary`, `customer_intent`, `agreements[]`, `next_steps[]`, `suggested_status_id`, `suggested_tag_ids[]`, `criteria[]`, `abstention_reason`. В каждом смысловом выводе — существующие segment IDs и время. Provider/model/prompt/rubric/transcript/input hash/cost/runtime сохраняет worker, а не доверяет их значения модели.

Неполный transcript, неизвестный speaker role, неверные evidence, неподходящая rubric → partial/needs_review/insufficient_evidence. Никаких высоких оценок или primary по умолчанию. Второй LLM-judge полезен как эксперимент, но не заменяет схему, детерминированные правила и эталонную человеческую разметку.

## Контроль качества

Предложение для пилота: 30–50 обезличенных звонков разных исходов/длительности/качества и клиентов с повторными обращениями, часть оставить вне настройки промпта. Разметка руководителя по критериям, типам обращения и evidence. До production согласовать acceptable error, abstention, latency и стоимость на минуту. Числа — план выборки, не доказанное качество.

Измерять валидность схемы, правильность ссылок, ошибки определения ролей, расхождение оценки, precision/recall для тегов и долю отказов. Сырые confidence модели не показывать как вероятность правильности. Статусы сделок и внешние действия остаются под отдельными правилами.
