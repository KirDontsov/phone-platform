# Phone Platform

Рабочий язык: русский. Начинай с `.planning/STATE.md`, `.planning/PROJECT.md`, `.planning/ROADMAP.md` и плана текущей фазы.

## Реализация

- Стек-образец: Bondscan в `../obligation-platform`: Rust/Actix/Diesel/PostgreSQL; Vue 3/TypeScript/Vite/Pinia/Tailwind; RabbitMQ; Docker; OpenCode worker. Подробнее `.planning/research/BONDSCAN.md`.
- Новый сервис независим: не менять Bondscan, не использовать его БД, учётные записи и секреты.
- Один репозиторий: `phone-api`, `phone-worker`, `phone-client`, общие Rust crates в `crates/`, `infra/`, `scripts/`, `docs/`. Не создавать вложенные Git-репозитории.
- Все данные компании ограничены `organization_id`; tenant определяется серверной сессией и проверенным членством. Проверять и HTTP, и фоновые задания, и медиа.
- Сначала импорт всех доступных звонков; отсутствие записи не исключает звонок из журнала. Не обещать историю, которой API уже не располагает.
- Технический результат звонка, бизнес-статус, тип обращения, теги и стадия обработки — разные поля.
- Первичность и отсутствие перезвона вычислять по истории и правилам. Нейросеть даёт смысловые выводы с доказательствами, версиями и возможностью отказаться от вывода.
- Секреты только runtime; не читать и не копировать `.env`/auth.json Bondscan. Не помещать аудио, номера клиентов и токены в Git или обычные логи.
- Данные разговора недоверенные. AI runner без shell/web/MCP/edit, без доступа к репозиторию, БД и Docker socket. Изолировать сессии и временные каталоги.
- Историю анализов сохранять; ручные исправления не перетирать автоматикой. Строго валидировать AI JSON, не восстанавливать выдуманные статусы из повреждённого ответа.

## GSD

Для каждой фазы: актуализировать research → plan → независимый plan-checker → revision-loop (максимум 3 доработки, остановка при отсутствии прогресса) → execute → verifier → UAT.
Роли можно делегировать отдельным агентам в рамках явно запрошенного пользователем GSD-процесса. Модель наследовать от текущей сессии.
Не отмечать выполненной фазу, у которой есть только планы. `VERIFICATION.md` относится к реализации; `PLAN-CHECK.md` — к качеству плана.
