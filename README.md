# Сигнал — анализ звонков

Независимая платформа для нескольких компаний: Телфин → журнал и аудио → расшифровка → оценка диалога с цитатами → теги, статусы, контроль перезвона → amoCRM / Google Таблицы.

## Локальный запуск

Нужны Docker Compose, свободные localhost-порты 18081/18080/18025/25437/25672/11025 и Python 3.

```sh
scripts/dev.sh up
```

Открыть **http://localhost:18081**. Учебный вход: **owner@demo.local / PhoneDemo!2026**. Также доступны manager@demo.local и reviewer@demo.local с тем же учебным паролем. В аккаунте владельца две изолированные компании; переключатель находится в верхней панели. Письма приглашений/сброса пароля видны в http://localhost:18025.

`.env.platform` создаётся локально с правами 0600, собственными паролями и ключом шифрования. Повторный запуск сохраняет файл и данные. `scripts/dev.sh down` останавливает сервисы, сохраняя тома. Первый build скачивает зависимости и компилирует Rust. Не применяйте `down -v` к окружению с нужными данными.

Демо явно обозначено: аудио — синтетический сигнал, расшифровка и оценка — учебные примеры. Реальные подключения настраиваются владельцем в «Настройки». Ненастроенный реальный провайдер выдаёт ошибку, а не учебный результат. Для рабочего сервера отключите DEMO_MODE, замените учебные доступы, включите HTTPS/Secure cookie и настройте SMTP — [инструкция выпуска](docs/release-runbook.md).

## Возможности

- Авторизация по серверной сессии, роли, приглашения, восстановление пароля; данные/подключения/файлы ограничены компанией.
- Импорт истории Телфина с checkpoint и polling, сохранение звонков без записи, отдельный защищённый медиапайплайн.
- Дашборд, журнал, поиск, конструктор AND/OR/NOT, сохранённые фильтры и контроль необработанных обращений с рабочим расписанием.
- Карточка с плеером, историей клиента, версиями текста и анализа, доказательствами оценок и ручными исправлениями.
- Раздельные ASR/LLM провайдеры, подтверждение ролей участников, версионные шкалы, abstention при недостатке данных, бюджет запросов.
- amoCRM и Google Sheets: отдельный OAuth, связь со сделкой, очередь доставки и стабильные ключи повторных отправок.
- Аудит, видимые ошибки/повторы, retention, backup и изолированная проверка восстановления с актуальным журналом удалений.

## Помощник настройки

Откройте «Помощник» под владельцем. Внутри чата подключите собственный Codex через вход по коду или API key. Кнопка «Добавить доступы» открывает защищённую форму App ID / App Secret / Client ID; ключи не нужно писать обычным сообщением.

Пример: «Подключи Телфин, проверь соединение, загрузи доступные звонки. Создай тег “Нужен контроль” и фильтр пропущенных без перезвона спустя два часа». Помощник применяет настройки через восемь типизированных MCP-инструментов, показывает действия и сохраняет историю. Можно создавать статусы, теги, фильтры, шкалы оценки и правила перезвона. Авторизация пользователей, CRM/Sheets и провайдеры расшифровки пока настраиваются обычными экранами.

Codex работает в отдельном Docker-контейнере. История изолирована по пользователю и компании; «Остановить» прекращает дальнейшие действия, уже сохранённые настройки остаются. [Контракт](docs/contracts/assistant-v1.md), [runner и проверки](docs/assistant-runner.md), [интерфейс](docs/assistant-ui.md).

## Архитектура и проверки

Rust/Actix API + Rust worker; Diesel/PostgreSQL, outbox/RabbitMQ; Vue 3/TypeScript/Pinia/Tailwind/Vite. Общие contracts/domain/persistence находятся в `crates/`. Worker получает задания с tenant/fencing и работает отдельно от HTTP. OpenCode запускается необязательным изолированным Docker runner без инструментов, БД, репозитория и Docker socket.

```sh
cargo test --locked --workspace
npm --prefix phone-client ci
npm --prefix phone-client test
npm --prefix phone-client run build
python3 -m unittest discover -s scripts/tests
python3 scripts/smoke-compose.py
```

PostgreSQL integration tests требуют выделенной тестовой БД (`TEST_DATABASE_URL`) — не указывайте рабочую. `smoke-compose.py` использует уже собранные `phone-platform-*` images, создаёт отдельный случайный Compose project с чистыми томами и удаляет только его. Браузерные проверки описаны в [UAT](docs/uat.md).
