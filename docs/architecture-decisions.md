# Решения реализации

## Хранение доменных документов

API, worker и UI используют единый [контракт](contracts/platform-v1.md). SQL-таблицы organizations/users/memberships/sessions/token_grants/jobs/outbox_events/deletion_tombstones хранят поля, для которых нужны реляционные ограничения. Версионируемые предметные сущности хранятся в `documents`: `(organization_id,id)`, kind, parent_id, JSONB data, version, timestamps. Composite parent FK не допускает межфирменную связь, service-слой проверяет kind/принадлежность внешних ссылок, optimistic CAS защищает изменения. Это конкретизация изначального списка сущностей, а не отдельная таблица на каждое название в research.

Плюс для первого выпуска — одинаковые атомарные операции версий, child artifacts, audit и tombstone. Цена — схемы JSON проверяются Rust-сервисами, поэтому writes в обход сервиса не являются публичным интерфейсом. На 5000 звонках локальный профиль укладывается в тестовый порог; на большой истории фильтры и dashboard сейчас читают документы компании в память. SQL read models/индексированные проекции нужно вводить по измеренному профилю, не объявлять текущую реализацию доказанно масштабируемой до произвольного объёма.

## Очередь и повторные попытки

PostgreSQL jobs — источник истины; claim lease/fencing, heartbeat и завершение результата ограничены tenant/актуальным worker. Outbox публикует уведомления RabbitMQ, но потеря уведомления не теряет задание: worker опрашивает durable jobs. Это позволяет изолированно повторять синхронизацию, ASR, анализ, delivery и purge. Каждая платная попытка резервирует бюджет с монотонным fencing, включая ручной retry.

## История и обратные звонки

Звонки без записи сохраняются. WholeCall answered не считается разговором с сотрудником без bridged evidence. Primary/repeat и callback episodes считаются по доступной истории и coverage, отдельно от AI. Дашборд сначала вычисляет обработку обращения по полной истории, затем ограничивает исходные обращения фильтром: перезвон за пределами фильтра всё равно закрывает эпизод. Пользовательские ручные правки защищены CAS/lock; повторный импорт обновляет только провайдерские поля.

Основной канал актуализации — polling с overlap, сохранёнными checkpoint и ручной сверкой периода. Webhook-подписки из исходного исследовательского плана в первую поставку не вошли; отсутствие webhook не блокирует импорт и не имитируется endpoint-заглушкой.

## ASR и модели

Распознавание речи и смысловой анализ разделены. Непроверенные speaker labels не превращаются автоматически в роли; пользователь может подтвердить роли, создав новую immutable версию. Итоговый балл вычисляется сервером из валидированных критериев и цитат, а не принимается произвольно из ответа модели. Неизвестное качество/стоимость остаётся unknown/null. Demo работает только при явном DEMO_MODE и synthetic call.

OpenCode — отдельный приватный HTTP runner с запрещёнными инструментами. Для внешней модели нужен отдельно настроенный provider. Данные транскрипта недоверенные: runner не имеет shell/web/MCP/edit, repo/DB/Docker socket; запросы используют отдельные сессии с удалением после завершения.

## Приёмка

По последнему указанию пользователя разработка всех фаз выполняется автономно, без остановки на live gate первой фазы. Отсутствие разрешённой настройки внешних аккаунтов не заменяется выдуманным live PASS. Research/plan/revision evidence, код и локальные проверки фиксируются отдельно от настоящей полноты Телфина, качества русского ASR/LLM и итоговой пользовательской приёмки.
