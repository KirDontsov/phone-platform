# Телфин: подключение из обычных доступов

Фаза12. Пользователь получает от заказчика логины/пароли кабинета и АТС, а не API application keys. Основной путь: защищённая вставка/ввод → encrypted credential refs → fixed provision_telphin tool → вход в официальный API portal → trusted Call API application → token → /user/ client_id → проверенное encrypted connection. Секреты и HTML не передаются модели.

## Credentials и UI

Существующий POST /api/assistant/conversations/:id/credentials принимает:

- kind=telphin_pbx, config={login:string,password:string,official_url?:string}.
- kind=telphin_cabinet, тот же config, отдельная пара для billing/support. Эта пара не считается доступом в АТС и не используется на PBX login автоматически.
- kind=telphin, прежний config={host?,app_id,app_secret,client_id}, только advanced UI.

login1..256chars, password1..4096bytes; не trim пароль. official_url — только HTTPS *.telphin.ru/telphin.ru без userinfo/fragment/не443port. Это hint, не outbound URL: transport ходит только apiproxy.telphin.ru/altapi.telphin.ru; altapi выбирается лишь по точному host hint, остальные официальные portal links означают apiproxy. Логин/пароль обязательны; никакой guesses/autocrossuse двух пар. Summary.kind имеет тот же union, остальные поля unchanged. User/org/conversation ownership, AES-GCM,24hTTL, физический GC/consume/delete/restore unchanged.

Default card: «Доступ в АТС» — логин, пароль, необязательная ссылка. Есть защищённая вставка обычного текста и локальное заполнение редактируемых полей, без обязательного JSON. «Личный кабинет Телфин» отдельный выбор; API-ключи advanced. Несколько неоднозначных пар не угадываются. Composer обнаруживает credentials при paste/submit и локально передаёт исходный текст форме; не в Pinia, localStorage, messages, model или audit. После сохранения PBX ref кнопка «Подключить Телфин» отправляет обычную задачу с ref; вход в Codex при необходимости по прежнему UI.

## MCP/runtime

Добавляется девятый fixed tool provision_telphin {credential_ref:uuid,expected_revision:int>=0}, additionalProperties=false. Он принимает только PBX ref; cabinet возвращает typed needs_action/need_pbx_credentials с ясным объяснением, API ref направляет к существующему connect_telphin. Не появляется generic HTTP/browser/shell. Node validateTurn принимает три kinds; prompt объясняет выбор. Exact catalogs/native tests обновляются. API timeout60s и MCP tool timeout65s только для этого provider flow; total run180s/24calls сохраняются.

Public tool Event дополнительно может содержать action={code,message,url?}, созданный только provider/controller, не моделью. URL строго HTTPS apiproxy/altapi.telphin.ru, без query/userinfo/fragment/нестандартного port, path /login/ или /app/...; frontend повторно валидирует. Summary/status отражают needs_action/uncertain честно. Текст модели не парсится в HTML/произвольные ссылки.

Tool result: {result:{state:'connected'|'needs_action'|'in_progress'|'uncertain',attempt_id?,revision?,connection_id?,action?:{code,message,url?}}}. Только safe server messages + fixed official URL, никаких HTML/login/AppID/secret/cookie/token. Success означает реальный token + /user/ client_id validation + committed config, не только login/app creation. Import отдельно sync_telphin. get_workspace_configuration включает последние5safe provisioning attempts (id/state/action/app_marker, без account fingerprints/секретов).

## Authority, CAS и side effects

Перед HTTP: store.authorized_run/org→convo→run lock + originalsession/owner/membership/gen/TTL, own unconsumed PBXref, mandatory settings revision. Mutation/capability receipt под теми же locks, counter24/failed replay сохраняются. Работа HTTP выполняется ВНЕ DB transaction. Перед каждым outbound stage повторяется original authority; перед регистрационным POST атомарно фиксируется durable create_attempted. После HTTP перед connection write снова authority+globalrevision CAS и защита существующего manualconnection. Существующее подключение не заменяется автоматически; вернуть existing_connection/action_required, не создавать приложение.

Отдельный tenant document telphin_provision, parent=null, stable org+host+login fingerprint, содержит только safe external-artifact ledger: marker, state, create_attempted,run/receipt IDs, lease_until, safe app_path/action. Login/password/API keys/cookies/HTML в ledger отсутствуют. Stable marker «Phone Platform <org/account digest>» не раскрывает логин. Дополнительно singleton tenant document telphin_provision_gate (stable org-only ID) сериализует ВСЕ аккаунты/hosts этой компании. Gate хранит active attempt, state, lease_until и монотонный generation/fence. При reservation выдаётся fence; каждый Guard.before_request и beforePOST проверяет точный attempt/fence/lease под org lock и original authority. Старый guard после истечения lease/новой reservation не может отправить POST. Новая reservation после expired prePOST допустима только при отсутствии create_attempted/creation_forbidden и с увеличением fence. Pending/create_attempted/uncertain любой PBXref/host блокирует регистрацию другого аккаунта той же компании до reconciliation; существующее подключение проверяется снова. known failure ДОcreate освобождает gate conditional exactfence, ambiguous POST не освобождает. Org lock сериализует reservations. Pending lease блокирует параллельный account attempt; expired create_attempted не снимается и не превращается в новую регистрацию. Same call_id replay deterministic; changed args409. Закрытие чата не стирает safe external-effect ledger и не разрешает дубль.

Перед POST адаптер читает /app/ и ищет точный marker (полный проверенный список, bounded pagination); не принимает чужие совпадения/несколько matches. При новом POST lost response/timeout/5xx — uncertain, НЕ blind retry. Следующая попытка сначала читает ledger+existing apps и пытается прочитать exactowned app credentials. Если Телфин не выдаёт secret повторно или результат не доказан — needs_action/manual_reconciliation с прямой безопасной ссылкой. Никакого автоматического удаления приложений. При cancel/revoke in-flight приложение может уже существовать; late connection commit запрещён, безопасный ledger outcome сохраняется. Секреты, пришедшие после revoke, не сохраняются в обычных документах/логах.

Derived API config сохраняется только через shared save_connection_in_db + audit/receipt и expected revision. PBX ciphertext уничтожается после success; для failure доPOST остаётся доTTL для повторного входа, при явном delete уничтожается. Billing ref не consumed чужим flow. Restore отзывает session/capability/temporary refs и помечает ЛЮБОЙ незавершённый ledger/gate uncertain с creation_forbidden=true и fence increment, ДАЖЕ если snapshot был до create_attempted. marker/create_attempted сохраняются. Чтение/ручная сверка допустимы, новый POST послеrestore запрещён без доказанной reconciliation — snapshot не доказывает отсутствие позднего внешнего side effect. Ledger replay не возвращает credentials/чаты.

## Fixed portal adapter

Production transport: только HTTPS apiproxy.telphin.ru/altapi.telphin.ru; no arbitrary target/env override. Redirects вручную только same origin/443/allowlisted routes. GET /login/,/app/,/app/register/, app detail из проверенного sameorigin link; POST только login и register. FORM-url-encoded POST /oauth/token client_credentials; GET /api/ver1.0/user/ и существующие read-only проверки. Никаких callcontrol/DELETE/PBX config operations: Call API у провайдера шире read-only, но наш адаптер их не выполняет.

Private cookie jar на invocation, bounded body256KiB, total55s/perrequest8s, capped redirects/pages. Login HTML anonymous подтверждён: username/password + hidden _csrf_token, POST текущей формы с sameorigin Referer/CSRF. Скрытая registration form не наблюдалась: определять имя/тип/access по реально полученным labels/available options; выбирать только trusted + Call API. Required неизвестные поля/неоднозначный markup — typed unsupported_portal, не угадывать значения. Secret App ID/Secret извлекаются только из подтверждённой страницы details/registration, проверяются token+/user/; client_id числовой, источник currentauthorizeduser. Provider failure text никогда не выходит наружу.

MFA/CAPTCHA/OTP/отсутствие прав/неподдержанный portal — needs_action с конкретной причиной/официальной ссылкой. Никакого обхода MFA, угадывания OTP или запросов к чужому billing account. Логи только stage/code/attempt ID. Тестовый transport/driver инжектируется через trusted server bootstrap в тестах, не HTTP/env/query/моделью; production allowlist остаётся неизменной.
