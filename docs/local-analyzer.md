# Локальный OpenCode для удалённого сайта

После одноразовой настройки запуск на этом компьютере: `./start-analyzer.sh`.

Рабочая схема: удалённый phone-worker → внутренний model-runner:4096 → Docker SSH relay → зашифрованный reverse tunnel → локальный Docker connector → OpenCode для анализа текста или ASR-адаптер для распознавания. Сайт, очередь, БД и записи остаются на сервере; компьютер выполняет обращения к моделям и возвращает ответ. Компьютер и Docker должны работать, иначе запросы ждут повторной попытки.

Скопирована идея локального analyzer из Bondscan, но не его аккаунты, секреты или БД. Доступный Bondscan start-analyzer старее Docker-конфигурации на скриншоте и читает remote RabbitMQ/БД через local forwards. У Phone транспорт отдельный: remote worker посылает аудио HTTP через SSH; перенос доступа к удалённой БД на ноутбук не требуется.

## Одноразовая подготовка

1. Выполни `./start-analyzer.sh init`. Создаются отдельные Phone SSH ключи в `secrets/analyzer-ssh/`, защищённый pairing `secrets/analyzer-pair.env` и `.env.analyzer.local`. Уже созданные ключи и пароль не заменяются. Все приватные файлы вне Git, права600.
2. В `.env.analyzer.local` укажи `PHONE_REMOTE_SSH_HOST` и `PHONE_REMOTE_SSH_USER`, при необходимости SSH-порт. Нужен адрес именно сервера Phone Platform и отдельный разрешённый SSH-доступ. Секреты Bondscan не копируются.
3. Получи точные команды: `./start-analyzer.sh remote-instructions`. На сервер передаются только публичный клиентский ключ и pairing-файл по доверенному каналу. Приватный SSH ключ остаётся на этом компьютере. Публичный ключ добавляется разрешённому SSH-пользователю сервера.
4. Remote overlay `infra/compose.analyzer-remote.yml` добавляет отдельный rootless SSH relay в сеть сайта. SSH доступен на сервере только через127.0.0.1:18422; порт HTTP4096 доступен только внутри Docker. API/worker получают тот же `MODEL_RUNNER_PASSWORD` через защищённый pairing-файл. Не подключай одновременно server-side compose.ai.yml: alias model-runner должен принадлежать relay.
5. Получи публичные host keys сервера и relay по доверенному каналу, сверь fingerprints, закрепи: `./start-analyzer.sh pin --jump-public-key /путь/к/server.pub --relay-public-key /путь/к/relay.pub`. Скрипт откажется молча заменять изменившуюся привязку.
6. Запусти `./start-analyzer.sh`. Он поднимет собственный Docker project phone-analyzer, передаст Phone credentials по stdin в собственный volume и дождётся сквозной HTTP-проверки через SSH. Host ssh-agent/домашний auth OpenCode/Bondscan не подключаются.

Для текущей установки сервер — `dks@81.16.141.170`, сайт — `https://phone.bondscan.ru`; адрес и собственный Phone ключ уже настроены на этом компьютере. Инструкция установки сайта: [release-runbook.md](release-runbook.md). Новый компьютер проходит одноразовый pairing заново. До pairing можно запустить только локальный connector: `./start-analyzer.sh local`; это не включает туннель и не означает связь с сервером.

## Повседневные команды

- `./start-analyzer.sh` или `up` — локальный connector и туннель.
- `./start-analyzer.sh status` — состояния своих контейнеров.
- `./start-analyzer.sh doctor` — проверка сквозного туннеля и pairing.
- `./start-analyzer.sh down` — остановить только свой analyzer; ключи и pairing сохраняются.
- `./start-analyzer.sh public-key` — показать только публичный клиентский ключ.

Для следующего компьютера перенеси исходники и выполни init заново; новый публичный ключ нужно разрешить на сервере. Pairing с сервером настраивается явно; не заменяй живые ключи/пароль автоматически.

## Уже подключённый провайдер OpenCode

Провайдер этой установки — **RouterAI**. Если его вход уже сохранён в глобальном OpenCode, оператор переносит его командой `python3 scripts/import-opencode-settings.py --organization <UUID-компании> --provider routerai --install`. Поддерживаются существующие inline credentials и обычный API-доступ из глобального legacy auth-файла OpenCode; данные других приложений не используются.

Если на этом компьютере вход ещё не перенесён, выполни **`./start-analyzer.sh connect-routerai`**. Компания определяется из уже настроенного приватного runtime, вводить её ID или ключ не нужно. Откроется RouterAI: войди в свой существующий аккаунт и подтверди доступ Phone Platform. Приложение получит собственный доступ через PKCE, сохранит его локально с правами0600 и перезапустит только свой локальный коннектор. Авторизация других приложений не заменяется. Согласие и выбранный лимит расходов подтверждает сам пользователь; скрипт не покупает подписки и не запускает расшифровку.

В «Расшифровка → OpenCode → Уже подключённый провайдер» RouterAI предоставляет исходные **Parakeet Ultra** и **Nemotron 3.5 Transcribe**. Они используют доступ RouterAI; поле ключа в Phone отсутствует. Те же идентификаторы моделей в отдельном режиме OpenRouter используют другой провайдер и его доступ, автоматического перехода между ними нет. Пробы соединения не отправляют аудио. Стоимость RouterAI сохраняется отдельно в `provider_cost` / `provider_currency:RUB`; общий `cost` остаётся неизвестным, чтобы рубли не смешивались с другими валютами.

В этой установке Phone использует отдельную приватную копию существующих настроек провайдеров OpenCode. Повторно вводить ключ на сайте не нужно. Копируется только список моделей и доступ к провайдеру; команды, плагины, MCP, инструкции и чужие аккаунты не переносятся. Коннектор ограничен одной явно выбранной компанией: другая компания не получает его модели, сессии или ключи.

В «Настройки → Нейросетевой анализ» выбери OpenCode и модель из каталога. Внутреннее подключение Docker сервер настраивает сам, поэтому поля API-ключа здесь нет. «Проверить соединение» проверяет существующий доступ и наличие выбранной модели, не отправляя текст разговора.

Для оператора перенос выполняется `python3 scripts/import-opencode-settings.py --organization <UUID-компании> --install`. Источник — глобальный `~/.config/opencode/opencode.json`, результат — собственные `secrets/local-opencode.json` и Docker volume с правами0600. Содержимое ключей команда не выводит. После обновления этой копии перезапусти только локальный `model-runner`, чтобы он перечитал настройки; обычные `down`/`up` сохраняют volume. Один коннектор не перепривязывается к другой компании автоматически.

В «Расшифровка → OpenCode → Уже подключённый провайдер» доступен отдельный **APInex Voice STT**, если APInex настроен локально. Его выбирают явно, затем сохраняют настройки. Распознавание запускается отдельной командой; оно использует лимит или баланс существующего APInex. Это другой STT-сервис, его результат не подписывается именами Parakeet или Nemotron. При доступе к провайдеру по локальному HTTP адрес localhost в приватной копии заменяется на host.docker.internal; сам локальный прокси также должен работать.

## Отдельный доступ OpenRouter

В «Настройки → Расшифровка → OpenCode» выбери «OpenRouter (отдельный доступ)» и модель:

- `moondream/parakeet-ultra`;
- `nvidia/nemotron-3.5-transcribe`.

Адрес — `http://model-runner:4096`: на сервере это Docker relay, на локальном стенде — собственный connector. В поле «API-ключ OpenRouter» вводится ключ именно этой компании. Он сохраняется зашифрованно на сервере и передаётся только на время запроса; транспортный пароль берётся из runtime сервера отдельно. При смене провайдера/адреса нужен новый ключ; пустое поле сохраняет прежний только при том же назначении.

Обе модели есть в `infra/model-runner/opencode.json`. Закреплённый OpenCode1.18.10 не имеет нативного STT endpoint: `/asr/*` — явное расширение Docker connector, которое вызывает настоящий [OpenRouter STT API](https://openrouter.ai/docs/guides/overview/multimodal/stt). Текстовый анализ продолжает использовать нативные OpenCode sessions. Веса ASR не скачиваются на ноутбук: эти модели вызываются у провайдера OpenRouter, с его доступом и тарификацией. Авторизация Codex сама по себе их не подключает.

## Вход Codex через локальный компьютер

Серверный Codex обращается к OpenAI через этот же SSH-туннель и локальный защищённый CONNECT-прокси. Разрешены только auth.openai.com, api.openai.com и chatgpt.com по443; TLS не расшифровывается. Самому клиенту ключ прокси вводить не нужно. Это устраняет подтверждённый HTTP403 при прямом входе с сервера; обычный вход через аккаунт ChatGPT выполняется в карточке помощника.

Неудачная попытка переподключения сохраняет прежнюю подтверждённую авторизацию. Явный выход отзывает и действующую, и незавершённую попытку. При неопределённом результате сохранения после сетевого сбоя помощник блокирует выполнение до нового входа, чтобы не запускать другую учётную запись под прежними правами.

Сохрани настройки и нажми «Проверить соединение»: проверяются connector и ключ, без отправки аудио. Затем открой одну запись «Можно слушать» и запусти расшифровку. Этап, повтор и ошибки видны в карточке. Длинное аудио режется на части, отменённые задачи удаляют временные файлы. Метки участников сохраняются, роли менеджер/клиент автоматически не выдумываются.

## Границы проверки

Изолированная настоящая Docker/SSH проверка доказывает транспорт, а синтетический upstream проверяет ASR-протокол. Они не доказывают доступ/качество реального OpenRouter-аккаунта. Проверка на реальном сервере требует его адреса, собственных разрешённых ключей и pairing; качество речи — отдельного контрольного звонка.
