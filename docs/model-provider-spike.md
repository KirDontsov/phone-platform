# Изолированный OpenCode runner

Дата проверки: 2026-11-11. OpenCode закреплён на `opencode-ai@1.18.10`; это отдельный optional Docker-профиль `ai`. Телфин, ASR и модельные API во время инфраструктурной проверки не вызываются.

## Запуск

Сначала создайте локальную конфигурацию платформы через `scripts/setup-local.py`. Сгенерированный `MODEL_RUNNER_PASSWORD` хранится только в `.env.platform` и передаётся контейнеру как `OPENCODE_SERVER_PASSWORD`. Весь `.env.platform` в окружение runner не загружается.

```sh
python3 scripts/smoke-model-runner.py --build --up
```

Команда собирает образ, поднимает только `model-runner`, проверяет API и Docker-ограничения. Машинный отчёт сохраняется в `data/eval/model-runner-smoke.json` с правами `0600`. Флаг `--cleanup` удаляет только контейнер runner после проверки; другие сервисы остаются запущены.

Самостоятельный запуск без smoke:

```sh
docker compose --env-file .env.platform -f infra/compose.yml -f infra/compose.ai.yml --profile ai up -d --build model-runner
```

Порт `4096` доступен только сервисам сети Compose. Порт на хосте отсутствует. В worker укажите провайдер `opencode`, `base_url=http://model-runner:4096`, `model=providerID/modelID`; поле `api_key` содержит runtime-значение `MODEL_RUNNER_PASSWORD`. Worker использует HTTP Basic с именем `opencode`, проверяет deny-all конфигурацию и отключает каждый инструмент в сообщении. На каждый анализ создаётся отдельная сессия; после ответа она удаляется.

## Ключи модельных провайдеров

Необязательный локальный файл `secrets/model-runner.env` подключается только к runner и не создаётся автоматически. Каталог должен иметь права `0700`, файл — `0600`; не добавляйте его в Git. Разрешены переменные провайдеров с суффиксом `API_KEY` или `API_TOKEN`, например `OPENAI_API_KEY` или `ANTHROPIC_API_KEY`. Entry point передаёт дочернему процессу только такие переменные, настройки runner и стандартные системные пути. `DATABASE_URL`, ключ шифрования платформы, cookie/session-секреты и пароли брокера не передаются. Существующие учётные данные Bondscan не используются.

## Ограничения контейнера

- Непривилегированный UID/GID `10001`, read-only корневая файловая система, `cap_drop=ALL`, `no-new-privileges`, лимиты памяти и процессов.
- Пустой рабочий каталог `/work` и домашний каталог в `/tmp`; оба раздела — tmpfs, очищаются с контейнером. Нет монтирования репозитория, домашнего каталога пользователя, Docker socket или постоянного хранилища.
- Конфигурация в образе и inline-конфигурация запрещают все permissions и tools; MCP, plugins, instructions, LSP и formatter отключены. Автообновление, snapshots и sharing отключены.
- Сервер требует аутентификацию. Его пароль нужен только доверенному worker; не выдавайте его браузеру или пользователям компаний.

Разрешение `deny` и `tools=false` проверяются по фактическому `GET /config`, а не только по исходному JSON. Встроенные идентификаторы инструментов могут присутствовать в `/experimental/tool/ids`: это реестр; выполнение запрещено конфигурацией и дополнительно каждым запросом worker.

## Верификация

Smoke выполняет только запросы метаданных: `/global/health`, `/config`, `/experimental/tool/ids`, `/provider`, создание и удаление пустой `/session`. Он проверяет отказ `401` без пароля, точную версию `1.18.10`, deny-all правила, отсутствие MCP/plugins/автоматических действий, удаление сессии и реальные Docker limits/mounts/ports. Модельных prompts не отправляет.

Фактическая проверка `python3 scripts/smoke-model-runner.py --up` завершилась успешно: версия `1.18.10`, UID `10001`, `401` без пароля, запрет всех permissions/tools, MCP/plugins отсутствуют, пустая сессия создана и удалена. Docker inspection подтвердил read-only root, tmpfs, отсутствие bind/volume mounts и опубликованных портов, ограничения памяти/процессов и capabilities. Собранный локальный image ID: `sha256:512e3e83ce7c92b4709f2e175bf9be7c4cb337ca7b6f003fe0954566d6441408` (зависит от платформы/сборки). Полный машинный результат находится в локальном отчёте smoke. Каталог `/provider` может показывать встроенного подключённого провайдера без локально заданного ключа; это не проверка inference или доступа к платной модели. Качество анализа, совместимость конкретной модели со строгим JSON и стоимость остаются открыты до настройки отдельного провайдера и прогона размеченного набора разговоров. Наличие работающего HTTP runner само по себе эти проверки не закрывает.

Официальные источники: [server API](https://opencode.ai/v1/docs/server/), [configuration](https://opencode.ai/v1/docs/config/), [permissions](https://opencode.ai/v1/docs/permissions/). API-конфигурация проверяется с закреплённой версией образа, поскольку новые версии могут менять контракт.
