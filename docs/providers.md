# Worker и провайдеры

Реализация: `phone-worker/`. Секреты подключений хранятся зашифрованными в документах компании; `ENCRYPTION_KEY` — base64 от 32 байт, общий runtime-ключ API/worker. Параметры задач содержат идентификаторы, а не токены. Никаких доступов Bondscan сервису не требуется.

## Запуск и проверка

```sh
python3 scripts/run-local.py worker
cargo test -p phone-worker
phone-worker healthcheck
```

Тесты `tests/pipeline.rs` дополнительно используют отдельную PostgreSQL при заданном `TEST_DATABASE_URL`; без неё явно печатают SKIP. Не указывайте рабочую БД: тесты создают синтетические организации/задачи. `tests/model_http.rs` проверяет реальные HTTP-запросы на loopback-сервере без внешних аккаунтов. Проверки на реальных Телфине, ASR, LLM, amoCRM и Google остаются отдельным live acceptance после локальной настройки владельцем.

`DEMO_MODE=true` разрешает детерминированный учебный ASR/анализ только для звонка с `synthetic:true`. Демонстрационная запись содержит синтетический сигнал; текст и оценка иллюстрируют интерфейс и не распознаются из этого сигнала. Временные метки ограничены длительностью аудио. При `DEMO_MODE=false` отсутствие подключения приводит к `configuration_missing`, никогда к подстановке демонстрационного результата.

`MEDIA_ROOT/.worker-health.json` обновляется на простое и во время задания, содержит только timestamp, worker_id, state, error_code, имеет права 0600. Docker healthcheck требует свежести 90 секунд. Структурированные ошибки провайдеров содержат безопасный код; тела ответов, токены, номера и аудио не выводятся в обычные логи.

## Телфин

Конфигурация подключения `kind=telphin`:

```json
{"host":"apiproxy.telphin.ru","app_id":"LOCAL_APP_ID","app_secret":"LOCAL_SECRET","client_id":"LOCAL_CLIENT_ID"}
```

Допустимы только `apiproxy.telphin.ru` и `altapi.telphin.ru` по HTTPS, редиректы запрещены. Worker проверяет доступ к клиенту, принадлежность call/CDR и время каждого звонка. OAuth client credentials обновляется по истечении срока и однократно после 401. JSON автоматически распаковывается из gzip, ответ ограничен 8 MiB. Для 429 сохраняются задержка и `next_request_at`; последующие задания подключения не обходят паузу.

`sync` принимает `from`, `to`, `all_available`; периоды режутся на семидневные окна с секундным overlap. Страница, эффективный размер, хеши и checkpoint сохраняются вместе с импортом в одной fenced-транзакции. Повторная страница/изменение контракта/чужая строка прерывают импорт без ложной полноты. Идентификатор звонка стабилен внутри компании и подключения; raw snapshot и CDR сохраняются отдельно. Отсутствие записи не удаляет звонок. Технический `answered` сам по себе не доказывает разговор с сотрудником: `human_connected` требует `bridged`; длительность человеческого разговора берётся из bridged_duration.

Обычный старт — 30 дней; `all_available` без подтверждённой нижней границы использует ограниченное поисковое окно и оставляет coverage неполным. Для известной границы задаются `history_start` (ISO date/time) и `history_start_verified:true`; только завершённая выгрузка до подтверждённой границы может пометить coverage полным. Не заявляйте историю, уже недоступную API. Подтверждённый interval сохраняется на подключении; завершённый polling продлевает его только при перекрытии с уже сверенным interval. Разрыв синхронизации не считается доказанной полнотой. Периодический polling раз в пять минут повторно сверяет последние два дня; поздние записи догружаются отдельными retry-задачами. Старую позднюю запись за пределами overlap можно догрузить повторной синхронизацией периода.

Сопоставление сотрудников использует `extension_id`/`extension_number` из CDR и точное совпадение с membership.extension. Если API возвращает только ID, оператор может задать проверенный `extension_mapping:{"8":"123"}` в конфигурации подключения. ID добавочного не считается его номером. Неизвестный номер, отсутствие сопоставления и несколько сотрудников показываются явно; автоматически загружать справочник добавочных пока не реализовано. После изменения mapping повторите синхронизацию нужного периода.

Записи скачиваются по проверенному `record_uuid` через API своего клиента, а не по произвольному storage URL из CDR. Лимит 96 MiB, MIME и magic bytes проверяются; вычисляются SHA-256 и длительность ffprobe. Файлы записываются атомарно с fsync в приватный каталог `MEDIA_ROOT/<organization_id>/…`; ссылки/выход за tenant-каталог отвергаются.

## ASR

`kind=asr`, OpenAI-compatible multipart endpoint:

```json
{"provider":"openai","base_url":"https://api.openai.com/v1/","api_key":"LOCAL_SECRET","model":"YOUR_ASR_MODEL","response_format":"verbose_json"}
```

Модель выбирается владельцем и должна поддерживать нужный `response_format`. `diarized_json` добавляет `chunking_strategy=auto`. При ответе только с текстом точных временных меток нет: сегмент помечается `whole_recording_only`. Speaker A/B не превращается автоматически в менеджера/клиента; по умолчанию `role_confidence=uncertain`, итоговая оценка отказывается от уверенного вывода. После проверки схемы каналов можно явно настроить `roles_verified:true` и `speaker_roles:{"A":"manager","B":"client"}`.

Файлы более 24 MiB режутся ffmpeg на WAV mono 16 kHz по 600 секунд; timestamp смещается относительно исходной записи. Размер каждого chunk проверяется, максимум 144 chunk. Процесс вызывается аргументами без shell, с очищенным окружением, таймаутом и уничтожением при отмене. Временные файлы удаляются и при ошибке. Настоящее качество русской речи и диаризации требует контрольной выборки реальных разрешённых записей.

## Анализ LLM

`kind=analysis`, OpenAI-compatible JSON chat:

```json
{"provider":"openai","base_url":"https://api.openai.com/v1/","api_key":"LOCAL_SECRET","model":"YOUR_MODEL","timeout_seconds":120,"max_output_tokens":2048,"estimated_cost_per_run":0.01,"budget_daily":10}
```

Также поддерживается `provider=http`: POST `<base_url>/analyze` со структурированным входом и Bearer-токеном, ответ — объект результата по контракту. Произвольные хосты запрещены; для частного совместимого сервера оператор явно задаёт `PROVIDER_ALLOWED_HOSTS` в runtime worker/API. HTTP разрешён только для `model-runner` и явно разрешённых model hosts. Это административная настройка, не поле компании.

OpenCode через приватный HTTP runner:

```json
{"provider":"opencode","base_url":"http://model-runner:4096","api_key":"LOCAL_MODEL_RUNNER_PASSWORD","model":"providerID/modelID","timeout_seconds":120}
```

Используйте `infra/compose.ai.yml`, профиль `ai`; pinned OpenCode 1.18.10. Пароль Basic пользователя `opencode` — runtime `MODEL_RUNNER_PASSWORD`; ключи выбранной модели находятся только в отдельном `secrets/model-runner.env` (не Git). Runner не получает репозиторий, БД, Docker socket или домашний каталог оператора; root filesystem read-only, отдельные tmpfs, nonroot, cap_drop ALL. Конфигурация запрещает все permissions и MCP. Worker дополнительно проверяет `/config`, получает все `/experimental/tool/ids`, выключает каждый инструмент в запросе, создаёт новую сессию и удаляет её после ответа. Ошибка удаления сессии видима как `runner_cleanup_failed`; повторное использование чужих сессий отсутствует. Передача `Codex` осуществляется только через отдельно настроенного провайдера OpenCode; логин/доступность модели без credentials не заявляются.

Текст разговора передаётся как недоверенные данные. Строгий domain validator требует все критерии выбранной immutable rubric, существующие status/tag IDs, точные цитаты с segment_id/start/end и допустимые оценки. Итог вычисляется сервером с весами rubric; неизвестные роли и недостаток доказательств приводят к abstention/null. Повреждённый JSON не ремонтируется выдуманными значениями. Сохраняются версии transcript/rubric/prompt/provider/model, input hash и история результата. `rubric_version` — бизнес-версия шкалы, отдельно от revision строки БД. Ручной lock/статусы/теги и заметки не затираются автоматикой.

Ежедневный budget — предварительная оценка расходов: reservation с advisory lock компании создаётся перед каждой попыткой запроса по монотонному fencing; ручной retry не переиспользует старую reservation. Фактическая цена неизвестна без доверенных тарифов/биллинга, не подставляется из текста модели. OpenAI usage берётся из transport envelope, OpenCode — из `info.tokens`/`info.cost`. Лимит контекста 160 KiB, max_output_tokens ограничен 128–8192.

## amoCRM и Google Таблицы

OAuth authorize/exchange/refresh доступны через API; state привязан к серверной сессии API. Refresh сериализуется DB advisory lock и сохраняет новый refresh token зашифрованным. При revocation показывается требование переподключения.

amoCRM `kind=amocrm`: `{account_domain,client_id,client_secret,redirect_uri}`; OAuth добавляет `{access_token,refresh_token,expires_at}`. Domain должен принадлежать `*.amocrm.ru` либо `*.kommo.com`. Поиск возвращает контакты и связанные сделки; неоднозначные совпадения выбирает пользователь. Для доставки нужна явно сохранённая external_link с deal_id. Примечание содержит стабильный marker компании/звонка/версии анализа, резюме, оценку и ссылку. Перед созданием worker ищет marker среди существующих примечаний; ограничение сверки — 5000 заметок, далее видимый retry без слепой записи.

Google `kind=sheets`: `{client_id,client_secret,redirect_uri,spreadsheet_id,sheet_name,column_mapping}`. OAuth scope — spreadsheets. Колонка A всегда содержит стабильный ключ `<organization_id>:<call_id>`; не удаляйте её. Пример mapping, совпадающий с настройкой интерфейса:

```json
{"call_id":"A","date":"B","phone":"C","result":"D","score":"E","summary":"F","call_link":"G"}
```

Дополнительные поля: contact_name, employee, direction, duration, status_id, tag_ids, contact_kind, delivery_marker; алиасы started_at/provider_result. Колонки A…AZ уникальны, неизвестные поля и переопределение ключа отвергаются. Массивы сериализуются JSON-строкой. Диапазон от A до последней настроенной колонки управляется интеграцией, пробелы mapping очищаются; пользовательские формулы размещайте правее. Используется `valueInputOption=RAW`: текст клиента не исполняется как формула. Перед каждым upsert ключ ищется заново, поэтому перестановка строк между доставками допустима; дубликаты ключа — ошибка. Ограничение 100000 строк/8 MiB ответа, не бесконечная загрузка листа.

Экспорт одного звонка в один provider сериализуется advisory lock между worker-процессами; delivery фиксируется до внешней записи. Версия анализа и marker закреплены на delivery. После потерянного ответа доставка становится `uncertain`: worker сначала ищет marker/ключ и не повторяет POST/append вслепую. Для Sheets найденная строка обновляется PUT, существующий call key не создаёт новую строку. Проверка ключа и запись Google API не образуют атомарную транзакцию с ручной сортировкой: на время доставки избегайте параллельного редактирования управляемого диапазона. Восстановление unresolved uncertain требует проверки внешнего результата оператором; это сознательное ограничение ради отсутствия дублей. Ошибка интеграции не блокирует журнал/ASR/анализ.

## Надёжность и удаление

PostgreSQL — источник истины очереди. Claim/heartbeat/fencing не позволяют просроченному worker завершить задачу; результаты и successful completion фиксируются одной транзакцией. Перезапуск подхватывает lease-expired job. RabbitMQ — необязательные durable подтверждённые outbox-уведомления; потеря брокера не теряет задания. Состояния retry/failed/uncertain видны API и могут повторяться оператором после устранения причины. Внешний HTTP имеет семантику at least once с описанной сверкой результата.

`purge` удаляет записи, transcripts, analysis, raw snapshots, ссылки и delivery, оставляет редактированный call stub для ссылочной целостности заданий и tombstone, препятствующий воскрешению при позднем импорте/retry. `retention` применяет сроки компании и ставит purge; также удаляет не привязанные к recording файлы своего tenant старше 24 часов, оставшиеся после аварии между fsync и DB commit; удаление записи в UI немедленно закрывает доступ. Backup/restore и очистка внешних систем требуют отдельных эксплуатационных правил владельца; автоматическое удаление чужих заметок/строк не выполняется.

В настройках Телфина доступно необязательное JSON-сопоставление `extension_mapping`, например `{"12345":"101"}`: ID внутреннего номера из АТС → добавочный сотрудника. Значения должны быть непустыми строками. Сверьте ID с АТС и укажите тот же добавочный в «Сотрудники и доступ»; worker не угадывает номер по неизвестному ID. Пустое поле сохраняется как `{}`.

### Уточнения review 2026-11-12

Вход анализа содержит UUID allowlists и определения `tag_definitions` / `status_definitions` с названиями, чтобы модель могла сопоставить смысл меток с разговором. Явно отключённый ASR/analysis не заменяется учебным провайдером даже в DEMO_MODE.

После неоднозначной внешней записи delivery сохраняет `requires_reconciliation` через ошибки чтения/refresh и повторные попытки. Возврат к обычному POST/append без подтверждения результата запрещён. Локальные ошибки настройки сделки/колонок проверяются до состояния attempting; успешная подтверждённая доставка снимает этот флаг.
