# Откат

Перед обновлением сохраните backup, ENCRYPTION_KEY отдельно и image IDs (`docker compose … images --format json`). Не используйте `down -v`: эта команда удаляет данные.

Если схема совместима, остановите API/worker, восстановите предыдущие версии исходников/образов, соберите и запустите `up -d --wait`. Проверьте `/ready`, вход и журнал. Не допускайте одновременно работников несовместимых версий.

Если схема несовместима, сначала сохраните текущую БД и актуальный deletion ledger; выполните проверку старого backup в изолированной БД по backup-restore.md. Только после проверки выделите новое окружение с восстановленной БД/медиа и старым приложением. Переключение production endpoint — отдельная операция выбранного оператором сервера. Не восстанавливайте старую БД поверх работающей без rehearsal и сохранённого ledger: это может вернуть ранее удалённые разговоры.

В текущей поставке базовая миграция additive и идемпотентна. Автоматического разрушительного downgrade нет; скрипт проверки backup никогда не подменяет рабочую БД.
