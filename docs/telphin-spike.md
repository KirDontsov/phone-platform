# Телфин: первая выгрузка истории

Python 3.11+; внешние Python-пакеты, Docker и база платформы для этого прототипа не нужны. CLI выполняет только OAuth и GET-запросы; настройки АТС не меняет.

## Локальная настройка

```bash
cp .env.example .env
chmod 600 .env
python3 -c 'import uuid; print(uuid.uuid4())'
```

Последняя команда выдаёт новый несекретный `PHONE_ORGANIZATION_ID` для первой компании. Сохраните его стабильным. Локально заполните `.env`: organization UUID, OAuth App ID/App Secret **доверенного (trusted) приложения**, числовой `TELPHIN_CLIENT_ID` клиента АТС. App ID и client ID АТС — разные значения. Доступ пользователя должен быть уровня клиента, а не одного добавочного или группы. `access=read_only` допустим. Для нескольких компаний используйте отдельные файлы, например `secrets/company-a.env`/`secrets/company-b.env` (mode 600), и отдельные каталоги внутри `data/`.

Секреты не передаются через аргументы, чат или Git. Переменные окружения имеют приоритет над env-файлом; пустые значения окружения также переопределяют файл. Env-файл читается как данные: без `source`, `$()` и подстановок. В quoted values внешние кавычки удаляются, inline comments не поддерживаются.

```bash
python3 scripts/telphin-spike.py probe
python3 scripts/telphin-spike.py --env-file secrets/company-a.env probe
```

`probe` проверяет OAuth, `/user/`, совпадение client ID и уровень пользователя. В вывод не попадают login, номера, токены и ссылки записей. OAuth `scope=all` сам по себе не доказывает полный доступ. Право читать историю окончательно проверяет export; probe явно возвращает `call_history_permission=not_yet_tested`.

Разрешены HTTPS-хосты `apiproxy.telphin.ru` и `altapi.telphin.ru`; redirects блокируются даже на том же хосте. TLS-проверка обязательна. На macOS дополнительно загружается `/etc/ssl/cert.pem`, если не задан `SSL_CERT_FILE`. При `tls_error` настройте доверенный CA bundle; не отключайте проверку сертификата.

## Контрольный период

```bash
python3 scripts/telphin-spike.py export \
  --from 2026-11-01 --to 2026-11-02 \
  --output data/company-a/control-1
```

Даты без времени означают полночь UTC; ISO-время требует timezone, например `2026-11-01T10:00:00+03:00`. Временная точность запросов — секунды. `init_time_gmt` проверяется на принадлежность запрошенному окну, дробные секунды сохраняются. Фактическую включённость краёв и смысл временного фильтра ещё нужно подтвердить на своей АТС: расхождение вызывает ошибку, а не молчаливое отбрасывание звонков.

Обрабатываются все строки истории без фильтра по результату/направлению/записи, включая пропущенные, внутренние и без аудио. Логический вызов определяется `call_uuid`; плечи CDR сохраняются отдельно. Неотвеченное плечо при ответе другим сотрудником не меняет технический результат whole call.

Параметры: `--window-days` (1–31, default 7), `--per-page` (1–1000, default 100), `--max-pages` на окно (default 10000). Это **локальные защитные лимиты**, а не доказанные пределы Телфина. Ответы проверяются по echoed page/per_page/order. Даже короткая непустая страница не завершает обход: нужна пустая страница. Повтор одной страницы, изменение effective per_page, неверный формат, чужой client_owner_id, 400/404/403 не считаются концом истории.

## Вся доступная история

```bash
python3 scripts/telphin-spike.py export --all-available \
  --max-windows 52 --window-days 7 \
  --output data/company-a/all-1
```

Режим идёт назад ровно в пределах бюджета окон, перекрывая границы на секунду. Пустые окна не означают начало истории и не останавливают поиск. Если подтверждённой нижней границы нет, результат — `partial_unknown_lower_bound`, exit 2. Увеличьте бюджет либо задайте известный явный диапазон через `--from/--to`. Нет способа доказать retention одним отсутствием строк; пока CLI **не объявляет всю историю подтверждённо полной**.

Большой backfill может исчерпать общий часовой бюджет API вашей АТС. При 429 или исчерпании Remaining сохраняется время следующей попытки по Reset/Retry-After; процесс завершается с кодом 75, не спит час. Повторите ту же команду после указанного времени. Persisted deadline блокирует даже новый probe этого экспорта. Другие процессы/приложения АТС в этом прототипе не координируются; общий распределённый throttle вводится в production-коннекторе.

## Возобновление и файлы

Та же команда с тем же каталогом продолжает checkpoint. Если `--to` опущен, при resume используется сохранённая верхняя граница. Компания, API host/client/app fingerprint и параметры диапазона связаны с каталогом; менять их при resume нельзя. После окончания повтор команды не перечитывает закрытые страницы. **Для свежей сверки создайте новый каталог с теми же явными `--from/--to`.** Поздние изменения и дрейф страниц требуют повторного сканирования; автоматический polling появится в фазе 3.

Файлы mode 600 в каталоге mode 700:

- `checkpoint.sqlite3`: durable source данных/страниц и прогресса; одна транзакция для данных страницы и checkpoint.
- `raw-pages/`: приватные исходные ответы; запись атомарно до commit, после crash возможен orphan страницы без checkpoint.
- `calls.ndjson`: дедуплицированные звонки, без вложенного CDR; organization/client binding в каждой строке.
- `legs.ndjson`: плечи последнего snapshot звонка; ordinal внутри snapshot, **не выдуманный provider leg ID**.
- `manifest.json`: scanned/unresolved окна, количества, исходы whole call, наличие record ID, варианты payload, ошибки/следующая попытка и ограничения полноты.

NDJSON и manifest — производные SQLite; при аварии они могут отставать, повтор команды восстановит их. `.lock` не допускает одновременной записи в один каталог. Symlinks отклоняются. Все выгрузки лежат внутри gitignored `data/`; не публикуйте этот каталог: в raw/SQLite/NDJSON есть номера и постоянные ссылки, даже если отчёт stdout обезличен.

`calls_with_multiple_payloads` показывает неоднозначность нескольких snapshots одного UUID. Исходные строки не теряются в raw-pages; текущий calls/legs — последнее наблюдение. Кардинальность UUID/CDR нужно сверить live, прежде чем использовать модель в production.

## Сверка с кабинетом

Подготовьте **локальный приватный** JSON (mode 600) с контрольными call UUID из разрешённого экспорта/кабинета. Время, АТС, фильтры и охват должны совпадать с экспортом CLI. Формат:

```json
[{"call_uuid": "synthetic-control-id", "cdr_count": 2}]
```

`cdr_count` необязателен; повтор UUID в reference запрещён. Это формат входа нашей сверки, не обещание формата экспорта Телфина. Если кабинет не выдаёт UUID, контракт сопоставления нужно уточнить до подтверждения полноты; не заменяйте контрольный набор копией собственной выгрузки.

```bash
python3 scripts/telphin-spike.py reconcile \
  --output data/company-a/control-1 \
  --reference data/company-a/reference.json
```

Нет сетевых запросов и потребности в credentials. `completeness-report.json` содержит количества missing/extra/CDR mismatch, company binding и незавершённые окна; UUID и номера не печатаются. Даже `comparison=matched` не подтверждает происхождение reference: `human_verified_same_period_timezone_filters_and_pbx` остаётся false до отдельного UAT. Manifest автоматически не повышается до live-verified.

## Проверки и коды завершения

```bash
python3 -m unittest discover -s scripts/tests -p 'test_telphin_spike.py'
```

Fixtures синтетические, documentation-derived/live-unverified. Проверяются границы доверия, реальные HTTP-контракты на fake transport, crash/resume и filesystem; реальные клиенты не используются.

Exit: 0 — probe/сканирование явного диапазона/сверка выполнены; 1 — безопасно описанная ошибка; 2 — неизвестная нижняя граница или несовпадение сверки; 75 — отложено из-за лимита; 130 — прервано оператором. `0` не означает подтверждённую полноту всей истории.
